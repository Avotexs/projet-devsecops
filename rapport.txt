1. VUE D'ENSEMBLE DU PROJET
================================================================================

SafeOps LogMiner est une plateforme DevSecOps complète pour l'analyse de 
sécurité des pipelines CI/CD. Elle collecte, analyse et détecte les 
vulnérabilités dans les logs des workflows GitHub Actions.

Objectifs principaux:
- Collecter les logs de pipelines CI/CD
- Parser et structurer les données de logs
- Détecter les vulnérabilités de sécurité
- Suggérer des corrections automatiques
- Détecter les anomalies comportementales avec ML
- Générer des rapports de sécurité
- Visualiser les données via un tableau de bord

4. PARTIE MACHINE LEARNING (ML) - DÉTAIL COMPLET
================================================================================

Le service ANOMALY-DETECTOR utilise des techniques avancées de Machine Learning
pour détecter les comportements anormaux dans les exécutions de pipelines CI/CD.

--------------------------------------------------------------------------------
4.1 CLASSE PRINCIPALE: AnomalyEngine
--------------------------------------------------------------------------------

Fichier: services/anomaly-detector/src/anomaly_engine.py

La classe AnomalyEngine est le cœur du système de détection d'anomalies.
Elle implémente deux algorithmes de ML:

1) ISOLATION FOREST (scikit-learn)
2) AUTOENCODER (TensorFlow/Keras)

--------------------------------------------------------------------------------
4.2 ALGORITHME 1: ISOLATION FOREST
--------------------------------------------------------------------------------

PRINCIPE:
    L'Isolation Forest est un algorithme d'apprentissage non supervisé qui
    isole les anomalies plutôt que de modéliser les données normales.
    
    Il fonctionne en créant des arbres de décision aléatoires. Les anomalies
    sont isolées plus rapidement car elles ont des valeurs inhabituelles.

PARAMÈTRES:
    - contamination = 0.1 (10% d'anomalies attendues)
    - n_estimators = 100 (nombre d'arbres)
    - random_state = 42 (reproductibilité)

IMPLÉMENTATION:
    ```python
    self.isolation_forest = IsolationForest(
        contamination=contamination,
        random_state=42,
        n_estimators=100
    )
    ```

UTILISATION:
    La méthode detect_with_isolation_forest() effectue:
    1. Extraction des features des exécutions
    2. Normalisation avec StandardScaler
    3. Entraînement du modèle
    4. Prédiction (-1 = anomalie, 1 = normal)
    5. Calcul du score d'anomalie

--------------------------------------------------------------------------------
4.3 ALGORITHME 2: AUTOENCODER (Deep Learning)
--------------------------------------------------------------------------------

PRINCIPE:
    Un autoencoder est un réseau de neurones qui apprend à compresser puis
    reconstruire les données. Les anomalies ont une erreur de reconstruction
    élevée car le modèle n'a pas appris à les représenter.

ARCHITECTURE DU RÉSEAU:
    ```
    ENCODER (compression):
        Input (input_dim) → Dense(32, ReLU) → Dense(16, ReLU) → Dense(8, ReLU)
    
    DECODER (reconstruction):
        Dense(8) → Dense(16, ReLU) → Dense(32, ReLU) → Output(input_dim)
    ```

PARAMÈTRES D'ENTRAÎNEMENT:
    - optimizer: Adam
    - loss: MSE (Mean Squared Error)
    - epochs: 50
    - batch_size: min(32, taille_données)

DÉTECTION D'ANOMALIES:
    - Calcul de l'erreur de reconstruction (MSE)
    - Seuil au 95ème percentile
    - Si erreur > seuil → ANOMALIE

IMPLÉMENTATION:
    ```python
    def _build_autoencoder(self, input_dim: int):
        # Encoder
        encoder_input = keras.Input(shape=(input_dim,))
        x = layers.Dense(32, activation='relu')(encoder_input)
        x = layers.Dense(16, activation='relu')(x)
        encoded = layers.Dense(8, activation='relu')(x)
        
        # Decoder
        x = layers.Dense(16, activation='relu')(encoded)
        x = layers.Dense(32, activation='relu')(x)
        decoded = layers.Dense(input_dim, activation='linear')(x)
        
        autoencoder = keras.Model(encoder_input, decoded)
        autoencoder.compile(optimizer='adam', loss='mse')
        return autoencoder
    ```

--------------------------------------------------------------------------------
4.4 EXTRACTION DES FEATURES
--------------------------------------------------------------------------------

Le système extrait 5 caractéristiques numériques pour chaque exécution:

1. duration_ms: Durée d'exécution en millisecondes
2. time_since_last: Temps écoulé depuis la dernière exécution (secondes)
3. duration_diff: Différence de durée avec l'exécution précédente
4. cpu_usage: Utilisation CPU (si disponible)
5. memory_usage: Utilisation mémoire (si disponible)

IMPLÉMENTATION:
    ```python
    def _extract_features(self, executions):
        features = []
        for exec_data in executions:
            features.append([
                duration,           # Feature 1
                time_since_last,    # Feature 2
                duration_diff,      # Feature 3
                cpu_usage,          # Feature 4
                memory_usage        # Feature 5
            ])
        return np.array(features)
    ```

--------------------------------------------------------------------------------
4.5 CLASSIFICATION DES TYPES D'ANOMALIES
--------------------------------------------------------------------------------

Une fois une anomalie détectée, le système la classifie en 4 catégories:

1. DURATION_ANOMALY
   - La durée d'exécution dévie de plus de 2 écarts-types
   - Exemple: Un build prend 5 minutes au lieu de 30 secondes habituelles

2. DELAY_ANOMALY  
   - Le délai entre exécutions est anormalement long ou court
   - Exemple: Pas de build pendant 2 jours alors qu'il y en a normalement 10/jour

3. BEHAVIOR_CHANGE
   - Changement significatif (>50%) dans le comportement
   - Exemple: La durée augmente soudainement de 60%

4. GENERAL_ANOMALY
   - Anomalie détectée mais ne correspondant pas aux catégories ci-dessus

IMPLÉMENTATION:
    ```python
    def _classify_anomaly_type(self, features, all_features, is_anomaly):
        if abs(duration - mean_duration) > 2 * std_duration:
            return 'duration_anomaly'
        elif abs(time_gap - mean_gap) > 2 * std_gap:
            return 'delay_anomaly'
        elif abs(duration_diff) > mean_duration * 0.5:
            return 'behavior_change'
        else:
            return 'general_anomaly'
    ```

--------------------------------------------------------------------------------
4.6 APPRENTISSAGE HISTORIQUE
--------------------------------------------------------------------------------

Le système peut apprendre des données historiques stockées dans TimescaleDB:

1. Récupération des 100 dernières exécutions pour un job donné
2. Combinaison avec les données actuelles pour l'entraînement
3. Stockage des nouvelles exécutions pour l'apprentissage futur

MODÈLES DE DONNÉES (stockage):

    BehaviorHistory (Table PostgreSQL/TimescaleDB):
        - job_id: Identifiant du job
        - timestamp: Date/heure de l'exécution
        - duration_ms: Durée en ms
        - status: success/failure
        - resource_usage: {cpu, memory}
    
    AnomalyReport (Table PostgreSQL):
        - job_id: Identifiant du job
        - anomalies: Liste des anomalies détectées (JSON)
        - summary: Résumé de l'analyse (JSON)
        - model_used: isolation_forest ou autoencoder
